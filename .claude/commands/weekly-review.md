이번 주의 Weekly Review를 작성해줘.

## 수행 절차

1. **이번 주 작업 파악**: 다음을 확인하여 이번 주 무엇을 했는지 파악한다.
   - `git log --since="1 week ago" --oneline` 으로 이번 주 커밋 확인
   - `docs/DAILY_REVIEW.md`에서 이번 주 daily review 읽기
   - `docs/TASK.md`에서 완료/진행중 작업 확인
   - `experiments/result/` 디렉토리에서 새로운 결과 파일 확인
   - 이번 주 대화에서 수행한 작업 내용 참조

2. **리뷰 작성**: 아래 형식으로 `docs/WEEKLY_REVIEW.md`에 이번 주 섹션을 추가한다.

```markdown
## Week of YYYY-MM-DD

### 이번 주 요약
- (1~2문장으로 핵심 요약)

### 완료한 것
- (구체적 성과 목록)

### 진행중인 것
- (아직 끝나지 않은 작업)

### 핵심 결과 / 발견
- (실험 결과, 수치, insight)

### 잘한 것
- (효율적이었던 프로세스, 좋은 판단)

### 개선할 것
- (시간 낭비, 반복된 실수, 프로세스 문제)
- **구체적 액션**: (다음 주부터 어떻게 바꿀지)

### 다음 주 계획
- (우선순위 순으로 3~5개)

### 연구 방향 점검
- (큰 그림에서 현재 위치, 방향 수정이 필요한지)
```

3. **IDEAS 정리**: `docs/IDEAS.md`에서 이번 주 아이디어들의 상태를 업데이트한다.

4. **TASK 정리**: `docs/TASK.md`에서 완료된 작업 이동, 새 작업 추가, 우선순위 재조정.

## 주의사항
- 리뷰를 작성한 후 사용자에게 보여주고 검토를 요청한다.
- 사용자가 수정/승인한 후에만 최종 저장한다.
- "개선할 것"에는 반드시 구체적 액션을 포함한다 (추상적 반성 X).
- Daily review가 없는 날이 있어도 git log와 대화 기록으로 최대한 복원한다.
